# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Security analysts, vulnerability-management teams and infrastructure engineers investigating a local environment.

## Product Purpose

RiskScope is an asset-aware vulnerability exposure and risk prioritization workstation. Its central workflow connects inventory and SBOM imports to evidence-backed correlation, contextual risk, potential paths, remediation, verification and reports.

## Positioning

Observations, deterministic automated assessments and attributed analyst judgments are separate, inspectable records. A vulnerability's global severity is not its environmental priority.

## Operating Context

A local browser workstation with SQLite persistence, offline feeds and synthetic ExampleCorp fixtures. An optional hosted mode uses Vercel for the frontend and Render for the API. No scanning, exploitation, patch deployment or LLM dependency.

## Capabilities and Constraints

The authoritative implementation brief is preserved in `docs/implementation-specification.txt`. Unknown intelligence remains unknown. Synthetic advisories are not factual claims about any real product. Live intelligence integrations are optional and disabled.

The user subsequently requested Vercel/Render deployment readiness, all synthetic test data, and anonymous temporary uploads without sign-in. Hosted sessions have separate synthetic-demo and upload workspaces; users must be explicitly informed of server processing, expiry, lack of backups and early loss on server sleep/restart. Local mode remains persistent.

## Brand Commitments

RiskScope. Precise, accessible, scan-friendly analyst language; no hype or unsupported security claims.

## Evidence on Hand

User-supplied specification and deliberately synthetic fixtures only. No real customer or organizational data.

## Product Principles

- Preserve provenance and history.
- Explain each automated decision.
- Never confuse installed software with demonstrated exploitability.
- Remain useful entirely offline.

## Accessibility & Inclusion

Keyboard-operable, labeled controls, visible focus, responsive layouts and explicit loading, empty and error states.

## Implementation Assumptions

The first implementation uses an English-language, single-user, loopback-only web workstation and a restrained evidence-led interface. Hosted mode remains an anonymous, bounded demonstration/testing service, not durable multi-tenant storage. User sign-in is explicitly excluded.
